## 一、三个必答问题

### 1. 为什么不用有监督？

**一句话**：真实审计里没有稳定、完整的历史异常标签；这份数据的 955 条标签只用于评估，不参与训练，也不参与规则定义。

**展开**：

- 数据里确实有 `Abnormal_Label`（955 条，13.64%），但它是事后审计结论，覆盖不完整，而且异常类型会变化。
- `Risk_Class` 与标签完全对应，属于泄漏列，已删除；`Abnormal_Type` 保留作对照，但不进入 111 个特征。
- 无监督训练 + 标签只评估，评估才可信；如果拿标签训练，再拿同一批标签评估，结果会偏乐观。
- 如果未来标签稳定、量足够，可以接有监督；但要做时间切分和外部验证。当前 3 天、CPU、可解释的目标下，无监督更合适。

**如果追问“有标签为什么不用”**：有标签 ≠ 能训练。标签是审计结论，不是业务发生前的信息；用它训练会让模型学到“审计员怎么标记”，而不是“异常长什么样”。

---

### 2. contamination 怎么定？

**一句话**：按审计容量反推，2% ≈ 140 条，是一个可解释的核查预算，不是真实异常率。

**展开**：

- 7,000 × 2% = 140 条。可以理解为 3 名审计员 × 2 天能认真核查的量（这是一个场景假设，不是数据事实）。
- contamination 只影响 `predict` 的阈值；异常分数的排序不变，所以 Top-K 名单也不变，变的只是“切多少条”。
- 我评估了 K=50 / 100 / 140 / 300 / 500 / 1000，精确率从 98.0% 降到 57.8%，召回率从 5.1% 升到 60.5%。K 由人力决定，不是模型决定。
- 如果审计容量是 350 条，就把 contamination 改成 0.05；不需要重新训练模型。

**如果追问“为什么不是 13.64%”**：13.64% 是这份数据的事后异常率，真实审计中未知；如果按 13.64% 切，等于用答案定阈值，评估会失真。

---

### 3. 缺失为什么不在清洗时直接删？

**一句话**：这份数据 0 缺失，删行没有收益；即使有缺失，直接删会改变分布、损失本就稀少的异常样本。

**展开**：

- 探查结果：7,000 行 × 59 列，缺失值 0；所以最终 0 行删除、0 行填充。
- 如果直接删行，会同时删掉正常和异常样本，改变金额分布和标签比例，后面的 Benford 与异常检测都会偏。
- 更稳妥的做法：先判断缺失机制（随机缺失 / 业务性缺失），再填补或加“缺失指示”列；异常样本少，不能随便删。
- 这份数据没有触发这个问题，但清洗流程保留了检查步骤（`missing_handling.csv`、`quality_check_*.csv`）。

## 二、数据与清洗

### 4. 115 维是怎么来的？

59 原始列 → 剔除 13 列（常量、泄漏、ID/名称、城市等）→ 46 列 → 10 个类别列 One-Hot 成 79 列（净增 69）→ 4 个金额/比率列用 `log1p + z-score` 替换原列（净增 0）→ **115 列**。

最终构成：

| 部分 | 列数 | 说明 |
|---|---:|---|
| One-Hot 类别 | 79 | 银行 9+9、省份 12+12、账户类型 6+6、支付渠道 7、发票类型 6、审批级别 4、边类型 8 |
| 数值特征 | 28 | 时间、账龄、评分、计数等 |
| 金额/比率 log1p+z | 4 | 交易金额、历史均值、交易/均值比、阈值比 |
| 标识列 | 2 | `Transaction_ID`、`Transaction_DateTime` |
| 标签列 | 2 | `Abnormal_Label`、`Abnormal_Type` |
| **合计** | **115** | 其中 **111 个特征**参与建模 |

对应 PPT 附录 A-1，可当场翻页核对。

### 5. 为什么保留省份，不保留城市？

- 省份 12 类，城市 25 类；城市基数更高，One-Hot 会更稀疏、增加噪声。
- 城市与省份信息重叠，保留省份已经能表达地域差异；城市留给人工核查。
- 被删的城市列：`Source_City`、`Destination_City`（见 `outputs/dropped_columns.csv`）。

### 6. 13 列为什么删？

| 类型 | 列 | 原因 |
|---|---|---|
| 常量 | `Currency` | 只有 CNY，零信息 |
| 标签派生 | `Risk_Class` | 与 `Abnormal_Label` 完全对应，泄漏 |
| 高基数 ID/索引 | 2 个 Node ID、2 个 Node Index、2 个 Entity ID | 上千个取值，不可泛化 |
| 名称/标识 | 2 个 Entity Name、`Invoice_ID` | 名称与 ID 重复；重复发票信号已由 `Duplicate_Invoice_Flag` 表示 |
| 高基数类别 | 2 个 City | 25 类，与省份重叠 |

完整清单：`outputs/dropped_columns.csv`。

### 7. 如何避免标签泄漏？

- `Risk_Class` 与标签完全对应，直接删除。
- `Abnormal_Type` 只在分析/评估时作对照，不进入 111 个特征。
- `Abnormal_Label` 只用于计算 ROC-AUC、PR-AUC、Top-K 指标，不参与训练。
- `Transaction_ID` 不作为特征；不做目标编码（target encoding）。
- 规则（Benford 数字 5）只看金额首位数字，不看标签。

### 8. 比率字段为什么仍然偏态？

- 比率有极端值（例如交易金额是历史均值的几十倍），`log1p` 只能压缩量级，不可能完全正态。
- 训练前再做 z-score，只是统一尺度；Isolation Forest 基于随机切分，对单调变换和残余偏态不敏感。
- 不强行做正态变换，是为了保留“极端比率”这个异常信号。

## 三、方法与评估

### 9. 为什么选 Isolation Forest？

- 无监督：不需要标签，符合审计现场“先筛后查”的流程。
- 适合多维表格：7,000 × 111，CPU 秒级，`n_estimators=200` 足够稳定。
- 不需要距离度量、不需要 GPU、不需要深度学习框架；`random_state=42` 可复现。
- 输出连续分数，可按 Top-K 排序，直接对应审计容量。

### 10. 为什么用 Benford，而不是只靠模型？

- Benford 是审计行业的成熟基线，能发现“金额首位数字分布异常”，解释成本低。
- 它只看金额，不看审批、发票、供应商、关系网络；模型能补多维组合。
- 两者 2×2 交叉后 Jaccard 只有 0.023，说明信号低重合、互补，而不是重复。

### 11. 整体 Benford 通过，为什么还有异常？

- 整体 MAD = 0.00405，属于“高度符合”；但整体 86.36% 是正常样本，正常样本把异常信号稀释了。
- 分组后：正常组 MAD = 0.00325，异常组 MAD = 0.03633（Nigrini 口径 >0.015 属于明显不符合）。
- 异常组数字 5 占 19.48%，期望 7.92%；整体数字 5 占 9.46%。
- 所以 Benford 是“初筛”，不是“判决”；整体通过不代表个体没问题。

### 12. 为什么 Benford 规则选数字 5？

- 数字 5 的偏差最大：整体实际 9.46% vs 期望 7.92%，异常组 19.48%。
- 规则简单、可解释：金额首位是 5 的交易进入 Benford 标记（662 条）。
- 这不是唯一规则；也可以用分组 MAD、数字 9、末位数字等。选 5 是为了让 2×2 有一个清晰、可复述的规则。

### 13. Top-140 召回只有 13.5%，是不是模型不好？

- 不是。审计容量只有 2%，召回必然低；精确率 92.1%、lift 6.75×，说明名单质量高。
- K=50：精确率 98.0%、召回 5.1%；K=100：96.0% / 10.1%；K=140：92.1% / 13.5%。
- 放宽到 K=1000：精确率 57.8%、召回 60.5%；要覆盖更多异常，就要接受更多人工作业。
- 审计是 triage，不是“一次抓完”；先保证名单质量，再按人力扩 K。
- 完整的 K 曲线和全表见 PPT 附录 A-2。

### 14. ROC-AUC、PR-AUC、Top-K 分别说明什么？

- ROC-AUC = 0.8795：整体排序能力较好。
- PR-AUC = 0.6466：在 6.33:1 不平衡下，比 ROC-AUC 更能反映异常类表现。
- Top-K 精确率/召回率/lift：直接对应“查前 K 条”的审计场景；这是汇报里最重要的指标。

### 15. 如果 contamination 改成 0.05 会怎样？

- 标记 350 条，召回更高、精确率更低；分数排序不变，只是阈值更宽。
- 这不是模型变好/变坏，而是审计容量的选择；用 K 曲线就能看出取舍。

### 16. 数据有没有时间泄漏？

- 当前是课程实践数据，按随机 `random_state=42` 复现；没有用未来信息训练。
- 真实落地要按时间切分：用过去的数据训练/定规则，用未来的数据评估；否则会高估效果。
- 本项目是无监督，标签不参与训练；但特征工程仍应避免“事后字段”（如审计结论、风险等级）。

## 四、结果与解释

### 17. 2×2 的四个格子怎么读？

| | 模型未标记 | 模型 Top-140 |
|---|---:|---:|
| **Benford 未标记** | 6,216 条，异常率 10.6% | 122 条，异常率 91.8% |
| **Benford 标记** | 644 条，异常率 26.2% | 18 条，异常率 94.4% |

- 双命中 18 条：异常率最高，优先核查。
- 仅模型 122 条：异常率 91.8%，是模型的主要贡献。
- 仅 Benford 644 条：异常率 26.2%，作为宽口径初筛。
- Jaccard = 18 / (18+122+644) = 0.023，低重合、高互补。

### 18. 模型能抓哪些异常类型？

覆盖 7/8 类；Top-140 中各类型的入选比例：

| 类型 | 入选 / 总数 | 比例 |
|---|---:|---:|
| 资金回流 Round_Trip | 42 / 107 | 39.3% |
| 重复发票 Duplicate | 28 / 109 | 25.7% |
| 税号不符 Tax_ID | 11 / 74 | 14.9% |
| 拆分交易 Split | 15 / 142 | 10.6% |
| 金额突增 Unusual | 17 / 175 | 9.7% |
| 高风险供应商 High_Risk | 11 / 141 | 7.8% |
| 时间聚集 Temporal | 5 / 92 | 5.4% |
| 跨省不匹配 Cross_Province | 0 / 115 | 0.0% |

- 强项：资金回流、重复发票（关系网络/发票特征明显）。
- 短板：跨省不匹配 115 条全部未进 Top-140；后续可补图特征或有监督模型。

### 19. 3 条案例是不是挑出来的？

- 3 条都是“模型-only”（Benford 没标记、模型 Top-140），用来解释模型在抓什么，不是用来调参。
- 完整字段在 `outputs/case_studies.csv`；案例是线索，不是定罪。
- 3 条分别是：重复发票（审批延迟 338.55 min、发票匹配 0.44）、高风险供应商（供应商风险 0.86）、拆分交易（金额 48.7 万、阈值比 0.974）。
- 重复发票案例的完整字段和模型排名（1 / 7,000）见 PPT 附录 A-3。

### 20. Top-140 里 11 条假阳性怎么办？

- 140 条中 129 条命中，11 条假阳性，假阳性率 7.9%。
- 审计场景可接受：人工复核会剔除；比“漏掉高风险”成本低。
- 后续可把复核结果反馈成规则/有监督样本，形成闭环。

### 21. 131 笔 500,000 元全是异常，怎么解释？

- 数据里 131 笔金额恰好 500,000 元，标签全部是 `Unusual_Amount_Spike`（金额突增）；`log1p` 后形成 13.1 处尖峰。
- 这是这批数据的一个重复金额模式，不代表“真实业务中等于 50 万就一定异常”。
- 真实审计中，整数大额集中是红旗，但仍要凭证、合同、审批链核实。
- 这个发现也说明：清洗阶段的分布图不是装饰，能直接暴露数据模式。

### 22. 模型分数怎么解释？

- `score = -score_samples`，越高越异常；没有特征级归因。
- 解释靠三层：2×2（规则/模型是否同时命中）、类型覆盖（抓哪些类型）、案例字段（金额、审批、发票、供应商、关系网络）。
- SHAP 不是必需；如果后续要做，可作为模型解释的补充，但不改变 Top-K 排序。

## 五、边界与下一步

### 23. 为什么不用深度学习 / SHAP？

- 数据 7,000 行、111 维表格，深度学习的边际收益有限；CPU + 3 天的约束下不划算。
- Isolation Forest 可解释、可复现、训练秒级；SHAP 不是评估指标，不能替代 Top-K 评估。
- 当前更重要的是把“数据 → 清洗 → 规则 → 模型 → 案例”讲清楚，而不是堆模型。

### 24. 规则和模型怎么合并？

- 不简单 OR；用 2×2 分层：双命中 18 条（94.4%）→ 模型-only 122 条（91.8%）→ Benford-only 644 条（26.2%）。
- 按容量取并集 784 条；如果只能查 140 条，优先双命中 + 模型 Top-140。
- 这就是“规则初筛（宽口径）+ 模型排序（高精度）+ 人工核查（分层）”的流程。

### 25. 只有 1 天怎么办？

- 直接复用 Top-140 名单 + 双命中 18 条；跳过 3 条案例的人工归因。
- 图用现成的 6 张；PPT 用 10 页主线 + 3 页附录；答辩只背 3 个必答问题。
- 先把“数据零缺失、0 行删除、Top-140 精确率 92.1%”讲清楚。

### 26. 这个项目能复现吗？

- `notebooks/01_explore.ipynb` → `02_clean.ipynb` → `03_analysis.ipynb` 顺序执行。
- 关键中间结果都在 `outputs/`：清洗后数据、Benford 表、分数、Top-140 名单、2×2、案例。
- 图表脚本：`outputs/report/build_report_figures.py`；PPT 脚本：`outputs/report/build_report_ppt.py`。
- `random_state=42`；CPU；无需 GPU/数据库/云服务。

## 六、30 秒总结（可背）

> 审计现场的问题是：7,000 笔交易人工逐笔看不完，规则只看单字段，异常样本少且标签不可靠。我用无监督方法做了一次异常识别：先清洗成 115 维、0 行删除；再用 Benford 看金额分布、Isolation Forest 看多维组合；按 2% 审计容量取 Top-140，精确率 92.1%、召回 13.5%、lift 6.75 倍；最后用 2×2 证明规则和模型互补，并人工归因 3 条案例。标签只用于评估，不参与训练。
